# 기능 및 화면 명세서 (SPEC.md)

이 문서는 기능 동작과 사용자 인터페이스 요구사항을 정의한다. 통합 배경과 정합성 결정을 포함한 기준 문서는 [revisions_and_decisions.md](revisions_and_decisions.md)이며, 구현 세부 작업은 [to-do.md](../to-do.md)를 따른다.

## 1. 제품 범위

- Next.js App Router 단일 코드베이스로 Windows용 Tauri v2 데스크톱 앱과 Android용 모바일 PWA를 제공한다. iOS PWA는 현재 범위에 포함하지 않는다.
- Supabase Auth, PostgreSQL, Storage를 사용하며 모든 금액은 정수 KRW로 관리한다.
- 주요 기능은 게임의 버전·픽업 일정, 개인 지출/예정 지출, 정기 구독, Google Play 및 Galaxy Store 포인트 지갑이다.
- 일정 종류는 `VERSION`과 `PICKUP`만 제공한다. 픽업 전반/후반은 날짜 범위 필터이며 별도 데이터 필드가 없다.

## 2. 인증 및 권한

- 개인 재무·게임 구독·메모·지출 데이터는 `user_id` 기준 RLS로 격리한다.
- 관리자는 Supabase 관리 콘솔 또는 서버에서 `app_metadata.role=admin`으로 지정한다. 클라이언트가 관리자 권한을 부여할 수 없어야 한다.
- 관리자는 공용 게임 카탈로그와 모든 사용자에게 공개되는 공용 일정을 관리한다. 일반 사용자는 게임/일정 요청을 제출하고 본인 요청을 조회한다.
- 게임 요청 승인 시 게임은 공용 카탈로그에만 추가되며 요청자의 내 게임 목록에 자동 등록하지 않는다. 관리자가 기본 아이콘을 지정한다.

## 3. 캘린더 및 일정

- 월간 타일에는 금액과 일반 지출 표시를 두지 않는다. 게임 아이콘, `VERSION`/`PICKUP` 기간 배너, 개인 메모 도트만 표시한다. 한 날짜에 메모가 여러 개여도 도트는 하나만 표시하고, 날짜 상세에서 해당 날짜의 메모를 모두 보여준다.
- 관리자 승인 후 공용 일정은 모든 사용자에게 보인다. 일정 수정은 관리자만 직접 수행하고, 사용자 제안은 승인 요청을 거친다.
- `VERSION` 또는 `PICKUP` 날짜가 바뀌면 연결된 `PLANNED` 지출의 `start_date`, `end_date`, `target_date`를 동기화한다. `CONFIRMED` 지출은 유지한다.
- 일정 바인딩 예정 지출은 종료일이 속한 달 예산에 귀속하고, 확정 지출은 결제일이 속한 달에 귀속한다. 취소 지출은 예산 집계에서 제외한다.
- 월 예상 소비액은 확정 지출과 예정 지출을 합산해 계산한다. 양수인 월별 예산이 없으면(행이 없거나 0원) 기본 예산을 사용한다. 적용 예산도 0원이면 비율 경고와 초과 확인을 생략한다.
- 변경으로 월 예상 소비액이 증가해 적용 예산의 100%를 넘으면 저장/확정 전에 확인을 요구한다. 적용 예산이 양수일 때만 적용한다.
- 데스크톱은 캘린더와 우측 상세/예산 사이드바를 제공하고, 모바일은 캘린더와 상세 바텀 시트를 제공한다.

## 4. 지출 및 포인트

- 지출 상태는 `PLANNED`, `CONFIRMED`, `CANCELLED`다. 사용자 지출의 물리 삭제는 금지한다. 예정 취소와 예정 취소 복구는 전용 RPC만 허용하며, 결제 환불은 별도 RPC로 처리하고 복구할 수 없다.
- 결제수단은 `WALLET`, `GOOGLE_PLAY`, `GALAXY_STORE`만 허용한다. 총 자산 차감 여부는 `deduct_from_asset` 토글로 기록하며, 켜져 있으면 결제 시 실결제액을 빼고 환불 시 복원한다. 오늘 결제는 기본 켬, 과거 내역 입력은 기본 끔이며 사용자가 변경할 수 있다.
- `WALLET` 결제와 한 스토어의 포인트 사용을 함께 허용한다. Google/Galaxy 포인트 지갑과 원장은 서로 분리하며, `point_platform`에 포인트 출처를 기록한다.
- Google Play 또는 Galaxy Store 결제에 대해서만 선택한 실제 결제 스토어의 적립률로 앱의 예상 적립량을 `floor(final_amount × earn_rate / 100)`으로 계산한다. WALLET 결제는 스토어 포인트 사용 여부와 관계없이 적립하지 않는다. 이 산식은 스토어의 공식 정산액을 보장하지 않는다. 사용자는 지갑 잔액을 원장 기록과 함께 수동 보정할 수 있으며, 계산은 서버 RPC가 수행한다.
- 포인트 사용과 적립, 자산 차감, 지출 확정은 한 트랜잭션으로 처리한다. 환불 시 사용 포인트를 반환하고 적립 포인트를 회수하며, 잔액이 부족하면 전체 환불을 거부한다.
- 구독 템플릿은 물리 삭제하지 않고 비활성화로 종료한다. 비활성화 시 기존 미결제 예정 회차는 취소 원인을 남겨 취소하고, 재활성화해도 자동 복구하지 않는다. 취소 회차는 같은 달에 자동 재생성하지 않으며 명시적으로 복구할 수 있다.

## 5. 게임 아이콘

- 사용자 커스텀 아이콘은 업로더 개인용 비공개 Storage 객체다. 원본 PNG/JPG/JPEG/WebP는 최대 5 MiB이며, 클라이언트에서 256×256 WebP로 변환한다.
- 변환 결과는 최대 100 KiB다. 이 한도를 넘으면 업로드를 거부하고 사용자에게 안내한다.
- 소유자는 로그인 세션으로 아이콘을 가져와 앱에서 표시하고 교체/삭제할 수 있다. 내 게임 목록에서 게임을 제거하면 해당 게임의 사용자 커스텀 아이콘 객체도 Storage에서 삭제한다. 공개 URL을 사용하지 않으며 업로드 후 다시 가져온다.

## 6. 오프라인 동작

- 유효한 인증 세션이 있을 때 캐시된 데이터를 읽을 수 있다. 오프라인 상태에서는 지출 쓰기를 비활성화한다.
- 세션이 만료되면 캐시된 개인 데이터를 표시하지 않는다.
- 온라인 복귀 시 `PLANNED`이고 KST 오늘보다 `target_date`가 과거인 모든 지출을 처리하는 필수 모달을 다시 표시한다. 모든 항목을 결제 확정, 예정 취소 또는 가능한 다음 일정으로 이동 처리해야 대화형 캘린더를 계속 사용할 수 있다. 오프라인에서는 캐시 조회를 허용하고 모달을 닫을 수 있으며, 미처리 항목은 온라인 복귀 시 다시 처리한다.
