# Gemini 전달용 검토 의견: Reviewer Agent 자동화 제안서

- 대상 문서: [ChronoLedger_pipeline_auto.md](ChronoLedger_pipeline_auto.md)
- 검토 목적: 제안서가 현재 ChronoLedger 협업 파이프라인의 문서·안전 규칙에 부합하고 실제 PoC로 진행할 수 있는지 검토한다.
- 검토 상태: 문서 검토 결과이며, 자동화 승인이나 구현 승인이 아니다.
- 기준: [협업 아키텍처](../md/multi_agent_collaboration_architecture.md), [AI 협업 사용 안내](ai-collaboration-usage.md), [협업 아티팩트 규약](../artifacts/README.md)

## Gemini 검토 요청

아래 판단을 독립적으로 검토해 주세요. 제안서와 관련 기준 문서, 인용한 줄의 현재 내용을 확인하고 근거가 틀리거나 빠진 부분은 명시해 주세요.

- 코드는 수정하거나 자동화를 구현하지 마세요.
- 제안서가 주장하는 효과, 보안성 및 자동화 범위가 실제 설계로 뒷받침되는지 평가해 주세요.
- 각 지적은 파일, 줄 번호, 근거, 영향 및 권고안을 포함해 주세요.
- 검토 결과는 문서 판단과 추가 검증이 필요한 가정을 구분해 주세요.
- 자동화 승인 여부를 추정하지 말고, PoC 전에 결정이 필요한 항목을 제시해 주세요.

## 요약 판정

현재 제안서는 수작업 리뷰 전달을 줄이려는 **아이디어 문서**로는 유효하지만, 기존 파이프라인을 대체하거나 바로 구현할 수 있는 실행 설계로는 부족하다. 우선 동일 Target SHA를 고정하는 단일 리뷰 PoC의 범위와 안전 조건을 정하고, 측정 결과를 바탕으로 채택 여부를 판단하는 것이 적절하다.

기존 협업 설계는 같은 Target SHA의 정적 리뷰와 테스트 결과, 격리 작업공간, 결과 스키마 및 사람의 최종 확인을 요구한다. 외부 Gemini 자동 호출·파일 전달은 현재 구성되어 있지 않으며, 안내 절차는 수동 전달을 전제로 한다.

## 발견 사항

### 1. 실행 대상 SHA와 diff 산출 방식이 기존 규약에 충분히 고정되지 않음

- 대상 위치: [제안서 §3 워크플로우 2단계](ChronoLedger_pipeline_auto.md), `run.json` 및 `git diff` 자동 추출
- 기준: [AI 협업 사용 안내 §4–5](ai-collaboration-usage.md), [아티팩트 규약](../artifacts/README.md), [협업 아키텍처 §4](../md/multi_agent_collaboration_architecture.md)
- 근거: 기존 절차는 Maker의 커밋 후 `target_sha`를 설정하고, Reviewer와 Orchestrator가 동일 SHA를 기준으로 판정한다. 제안서의 “최신 결과 파일” 또는 worktree의 일반 `git diff`는 어느 run·iteration·Base/Target 범위를 뜻하는지 명확하지 않다.
- 영향: 잘못된 worktree나 미커밋 변경, 오래된 run을 리뷰에 포함하거나 다른 SHA의 결과를 `review.json`으로 기록할 수 있다.
- 권고: 사용자가 지정한 run ID 및 iteration을 입력으로 받고, manifest의 Base/Target SHA를 검증한 뒤 정확히 `Base SHA..Target SHA` 커밋 범위에서 diff를 생성한다. 검사 중 HEAD/worktree가 예상과 다르면 중단한다. 임의의 “최신 run” 자동 선택은 하지 않는다.

### 2. 코드 및 변경 내용의 Gemini API 외부 전송 경계가 정의되지 않음

- 대상 위치: [제안서 §3 워크플로우 3단계](ChronoLedger_pipeline_auto.md), diff와 수용 기준을 Gemini API로 전송
- 기준: [협업 아티팩트 규약의 민감정보 금지](../artifacts/README.md), [협업 아키텍처 §3](../md/multi_agent_collaboration_architecture.md)
- 근거: 제안서는 diff 전송 전에 어떤 경로와 내용이 포함되는지, 비밀값·개인정보를 어떻게 탐지/제외하는지, 외부 전송 여부를 누가 승인하는지 설명하지 않는다. `.env`에서 API 키를 읽는 것만으로 전송 데이터의 보안이 확보되지는 않는다.
- 영향: 저장소 코드, 개인 데이터, 토큰 또는 환경설정 값이 외부 API 요청에 포함될 수 있다. API 키와 리뷰 대상 데이터의 보안은 서로 다른 문제다.
- 권고: 전송 대상 파일을 allowlist로 제한하고, 비밀정보 탐지와 민감 경로 차단을 수행하며, 전송 직전 사용자에게 전송 목록/요약을 확인시키는 명시적 승인 단계를 둔다. 차단 또는 검사 실패 시 호출하지 않는다. 데이터 보존·사용 조건과 모델/계정 선택도 PoC 전 확인한다.

### 3. 자동화 범위가 Reviewer 단계인지 전체 파이프라인인지 모호함

- 대상 위치: [제안서 §2](ChronoLedger_pipeline_auto.md), “완벽히 자동화”; [§3 워크플로우 4단계](ChronoLedger_pipeline_auto.md), “다음 단계(Orchestrator)로 이벤트 전달”
- 기준: [협업 아키텍처 §2](../md/multi_agent_collaboration_architecture.md), [AI 협업 사용 안내 §4–7](ai-collaboration-usage.md)
- 근거: 구현안은 주로 diff 전송 및 리뷰 파일 저장을 설명한다. Maker 구현, 격리 환경 테스트, 리뷰 지적에 따른 수정 반복, 사용자 승인 및 종료 처리를 자동화하는 구성은 정의하지 않는다. “이벤트”의 대상·프로토콜·실패 동작도 지정되어 있지 않다.
- 영향: 사용자는 Reviewer만 자동화하면서 Maker·테스트·승인까지 자동화된 것으로 오해할 수 있고, 리뷰 결과가 확인되기 전에 후속 작업이 진행될 수 있다.
- 권고: 1차 범위를 “리뷰 요청 생성 및 결과 초안 저장”으로 제한한다. API 응답은 리뷰 결과일 뿐 통과/병합 승인이 아니며, 사람이 스키마·근거·SHA를 확인하기 전에는 어떤 후속 자동 실행도 하지 않는다고 명시한다.

### 4. API 응답 검증 및 실패·재시도·중복 호출 처리가 없음

- 대상 위치: [제안서 §3 워크플로우 4단계](ChronoLedger_pipeline_auto.md)
- 기준: [아티팩트 규약](../artifacts/README.md), `artifacts/schemas/review.schema.json`
- 근거: 파일의 원자적 저장은 중간에 잘린 파일을 막을 뿐, 응답이 올바른 JSON인지, 올바른 run/iteration/SHA를 가리키는지, 기존 리뷰 스키마를 만족하는지는 확인하지 않는다. API 오류, 시간 초과, rate limit, 응답 잘림, 재실행 중복 호출의 처리도 없다.
- 영향: 형식 오류나 다른 실행의 결과가 유효한 리뷰처럼 저장될 수 있고, 실패가 성공 또는 누락으로 조용히 처리될 수 있다.
- 권고: 결과를 저장하기 전에 JSON 파싱, `review.schema.json` 검증, run ID·iteration·Base/Target SHA 일치를 모두 확인한다. 실패는 성공 형태로 대체하지 말고 상태와 비민감 오류 요약을 기록하며, 재시도 횟수·중복 방지 키·비용 한도를 정의한다. 검증 후 임시 파일에서 원자 교체한다.

### 5. 정량적 기대 효과의 측정 근거가 없음

- 대상 위치: [제안서 §4](ChronoLedger_pipeline_auto.md), 10초 이내·98% 향상·오류 발생률 0%
- 근거: 기준 작업 수, 측정 방법, 모델 응답시간·비용, 리뷰 품질 평가가 문서에 없다.
- 영향: 추정치를 보장된 결과로 오해해 자동화 비용과 오류 가능성을 과소평가할 수 있다.
- 권고: 수치를 목표/가설로 표시하고, 수동 리뷰 대비 입력 준비 시간, 전체 처리 시간, 유효 JSON 비율, SHA/스키마 불일치 수, 사람에 의해 확인된 유용한 지적 비율, API 비용을 실제 PoC 여러 건에서 측정한다. “오류 0%”는 보장 표현으로 사용하지 않는다.

### 6. 승인·일정 placeholder가 남아 있어 제안 상태가 명확하지 않음

- 대상 위치: [제안서 §5](ChronoLedger_pipeline_auto.md)
- 근거: 승인자와 검토 완료 희망일이 미지정이다.
- 영향: 제안서가 승인된 구현 계획인지 아이디어인지 독자가 판단하기 어렵다.
- 권고: 상태를 “검토 제안 / 승인 대기” 등으로 명시하고, 승인자와 일정은 실제 결정 전까지 미정으로 유지한다. 빈 placeholder를 완료나 승인 사실처럼 해석하지 않도록 한다.

## 권고하는 최소 PoC 게이트

1. 자동 구현·수정·병합 없이, 지정 run의 단일 Target SHA에 대한 Reviewer 호출만 수행한다.
2. 호출 전 정확한 run/iteration/SHA와 전송 파일 목록을 확인하고, 민감정보 검사가 통과한 뒤 사람의 승인을 받는다.
3. API 결과는 기존 `review.json` 스키마와 SHA 메타데이터를 검증한 후에만 저장한다. 오류 시 `blocked`/실패로 남기고 성공으로 처리하지 않는다.
4. 기존 수동 Copilot/Gemini Reviewer 절차를 유지하고, 동일 변경에 대한 결과를 비교한다.
5. 여러 실행에서 품질·처리시간·비용·실패율을 기록한 후 자동화 도입을 별도로 승인한다.

## 관련 기준과 문서 상태

- Gemini는 기존 안내에서 Reviewer 대안으로 언급되어 있지만, 실제 API 오케스트레이션이나 자동 파일 연동은 설정되지 않았다.
- 본 문서는 Gemini에 전달할 검토 기록이며, [자동화 제안서](ChronoLedger_pipeline_auto.md)를 승인하거나 수정한 것이 아니다.
- 제안서와 PoC의 승인 여부는 사용자가 결정해야 한다.
