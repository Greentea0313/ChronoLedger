## 2. R62 프리셋 탭 PC 좌우 분할·드래그 배치

- **현행**:
  - `조합 프리셋` 탭은 `PresetList`(카드 목록)만 보여 주고, 편집은 `PresetEditorDialog` 모달에서 함.
  - 모달 안에서 슬롯 목록(위)과 캐릭터 선택 그리드(아래)를 세로로 배치하며, 캐릭터를 클릭하면 빈 슬롯 끝에 추가·해제됨. 슬롯 순서는 위/아래 화살표 버튼으로 바꿈.
  - 프로젝트에 드래그 앤 드롭 라이브러리 없음(`@dnd-kit` 등 미설치).
- **제안 구조 (PC 전용, 모바일은 현행 모달 유지)**:
  - 좌측 사이드바: 보유 캐릭터 그리드 + 기존 `CharacterFilterBar`(보유 여부·레어도·분류·이름 검색).
  - 우측 메인: 선택한 프리셋의 제목·메모·슬롯을 바로 편집하는 인라인 편집 영역 + 프리셋 목록(선택 전환).
  - 추가 방식 2가지:
    - 좌측 아바타를 우측 슬롯으로 드래그해 놓으면 그 슬롯에 배치함(이미 다른 슬롯에 있으면 이동).
    - 우측 슬롯을 클릭해 "선택 중" 상태로 만든 뒤 좌측 아바타를 클릭하면 그 슬롯에 배치함. 키보드·터치 대체 경로를 겸함.
  - 슬롯 간 드래그로 순서 변경 가능하게 하면 기존 화살표 버튼 대체 가능함(화살표는 접근성용으로 유지 권장).
- **기술 판단**:
  - 신규 의존성 없이 HTML5 Drag and Drop으로 구현 가능함(PC 마우스 전용 범위이므로 충분함). 터치 드래그까지 필요해지면 `@dnd-kit` 도입을 그때 검토함.
  - 현재 `addCharacterToPreset`은 끝에 추가만 하므로, 특정 슬롯 위치에 넣는 순수 함수(예: `placeCharacterInSlot(ids, index, characterId, maxSlots)`)를 `character-utils.ts`에 추가하고 단위 테스트로 검증함.
  - 슬롯 상한 축소 시 비파괴 정책(§7.3.1, 상한 초과 프리셋은 늘리지 못함)을 새 배치 함수에도 그대로 적용해야 함.
  - 인라인 편집은 저장 전 상태가 있으므로 프리셋 전환·탭 이동 시 미저장 변경 경고 여부를 정해야 함.
- **결정 필요**:
  - 분할 레이아웃 적용 기준 너비: `md`(900px) 또는 `lg`(1280px).
  - 편집 방식: 우측 인라인 편집(저장 버튼) vs 현행 모달을 넓혀 좌우 분할.
  - 프리셋 저장 시점: 명시적 저장 버튼(권장, 현행과 동일) vs 배치 즉시 자동 저장.

## 3. R63 즐겨찾기·보유·미보유 3분류 + 즐겨찾기 순서 드래그

- **현행**:
  - `CharacterRoster`는 한 그리드에 표시하고 `sortCharactersFavoriteFirst`로 즐겨찾기만 앞에 정렬함.
  - 필터 칩은 `보유 여부: 전체 / 보유 / 미보유`임.
  - `user_characters.is_favorite`는 `is_owned`와 독립임(미보유 캐릭터도 즐겨찾기 가능).
  - 즐겨찾기 순서를 저장할 컬럼 없음.
- **제안**:
  - 보유 캐릭터 화면을 `즐겨찾기` / `보유` / `미보유` 3개 구역으로 나눔. 각 캐릭터는 한 구역에만 표시함(즐겨찾기가 우선).
  - 즐겨찾기 구역만 드래그로 순서를 바꾸고, 순서를 DB에 저장함.
- **DB 변경 (Opus 승격 조건 ① 해당)**:
  - `user_characters.favorite_sort_order INTEGER NULL` 추가 마이그레이션, `SCHEMA.sql`·`database.types.ts`·`TESTS.sql` 반영.
  - 기존 RLS는 본인 행 갱신을 이미 허용하므로 정책 추가는 불필요할 것으로 보임(마이그레이션 시 확인 필요).
  - 운영 미적용 상태를 견디는 폴백(`42703`/`PGRST204` 시 이름순)을 둠.
  - 대안: 순서를 `localStorage`에만 저장(R38 게임 순서와 같은 방식). DB 변경은 없지만 기기 간 동기화가 안 됨.
- **결정 필요**:
  - 미보유 캐릭터의 즐겨찾기 허용 여부(현행 허용). 허용하면 즐겨찾기 구역에 미보유 캐릭터도 흐리게 표시됨.
  - 순서 저장 위치: DB(기기 간 동기화, 권장) vs `localStorage`.
  - 프리셋 편집기 캐릭터 선택 목록에도 같은 3분류를 적용할지 여부.

## 4. R64 템플릿 분류별 아이콘

- **현행**:
  - `games.classification_schema`는 `{ rarities: string[], axes: [{ key, label, options: string[] }] }` 형식임.
  - DB `is_valid_classification_schema`가 옵션을 문자열로만 허용하므로, 아이콘을 넣으려면 형식과 CHECK를 함께 바꿔야 함.
  - 템플릿 저장 흐름(R57·R59)은 템플릿 컬럼만 갱신함.
- **제안**:
  - 첫 템플릿 생성 후(템플릿 활성 상태) `템플릿 설정 수정` 화면에서 레어도·분류 옵션별 아이콘을 등록함.
  - 저장 위치 후보:
    - (A) 별도 테이블 `game_classification_icons(game_id, axis_key, option, icon_url)` — 기존 스키마·CHECK 변경 최소, 관리자 전용 쓰기 RLS 필요. **권장**.
    - (B) `classification_schema` 안에 `option_icons` 맵 추가 — 조회는 간단하지만 Data URL을 넣으면 `games` 행이 커지고 모든 게임 목록 조회가 무거워짐.
  - 아이콘 형식은 기존 캐릭터 아이콘 규칙(256×256 이하 WebP Data URL, 길이 CHECK)을 재사용하되 분류 아이콘은 작게(예: 64×64) 제한하는 것이 적절함.
  - 표시 위치: 필터 칩, 캐릭터 설정 모달, (선택) 캐릭터 카드 모서리.
  - 분류 옵션 이름을 바꾸거나 지우면 아이콘도 함께 정리해야 함(R57 사용 중 옵션 삭제 차단 로직과 연동).
- **결정 필요**:
  - 아이콘 대상: 레어도만 / 분류 기준(속성·무기 등) 옵션만 / 둘 다.
  - 아이콘 표시 위치.
  - 저장 방식 (A)/(B).

## 5. R65 관리자 캐릭터 필터 `모든 게임` 제거·레어도 게임별 표시

- **현행 (`src/app/admin/page.tsx` 캐릭터 탭)**:
  - 게임 선택에 `모든 게임` 옵션이 있고, 이때 레어도 목록은 모든 게임 레어도의 합집합으로 표시됨.
  - 게임을 고르면 해당 게임 레어도만 표시하고, 게임 변경 시 레어도 필터를 초기화함(이미 동작).
  - 사용자 `캐릭터` 페이지 필터는 항상 선택한 게임 기준이므로 해당 없음.
- **방향**:
  - `모든 게임` 옵션을 제거하고 기본값을 첫 번째 게임(또는 마지막 선택 게임)으로 둠.
  - 그러면 레어도는 항상 선택한 게임 것만 표시되어 두 번째 요청도 함께 해결됨.
  - 게임 미선택 전제로 동작하던 분기(`!selectedCharacterGame`일 때 기본 라벨로 `캐릭터 추가` 버튼 노출 등)를 정리하고 관리자 페이지 테스트를 갱신함.
- **확인 필요**: 등록된 게임이 0개일 때의 빈 상태 문구.

## 6. R66 픽업 전용 캐릭터 생성 경로 (확인 결과)

- **결론**: 픽업 전용 캐릭터는 템플릿 없이 생성 가능하지만, **관리자 캐릭터 탭에는 직접 생성 버튼이 없음**. 다음 2가지 경로로만 생성됨.
  1. **관리자 일정 등록·수정**: 일정 종류를 `PICKUP`으로 고르면 픽업 캐릭터 선택 영역에 `[+ 새 픽업 캐릭터]` 버튼이 나옴. 이름(+ 이미지 선택)을 입력하면 즉시 `is_pickup_only = true` 캐릭터로 등록되고 선택 목록에 추가됨(`handleRegisterNewPickupCharacter`, R52 명세 U-04).
  2. **사용자 일정 요청 승인**: 사용자가 픽업 일정 요청에서 새 캐릭터를 제안하면(`pickup_new_characters`, 이름 필수·이미지 선택), 관리자가 승인할 때 `approve_schedule_request` RPC가 픽업 전용 캐릭터로 자동 등록·연결함(R52 명세 A1-Q2).
- **관리자 캐릭터 탭 현황**: 템플릿이 없는 게임은 `캐릭터 템플릿 생성` 안내 카드와 그 아래 픽업 전용 캐릭터 목록(수정·삭제)만 표시함. 템플릿이 있는 게임의 `캐릭터 추가`는 정식 캐릭터만 만들며, 픽업 전용 캐릭터는 등급·분류를 채워 정식으로 승격할 수 있음(U-05).
- **개선 제안 (선택)**: 캐릭터 탭에 템플릿 여부와 무관한 `[+ 픽업 전용 캐릭터 추가]` 버튼을 두고 일정 흐름의 인라인 등록 로직을 공용 함수로 재사용함. DB 변경 없음(기존 CHECK가 픽업 전용의 아이콘·등급 생략을 이미 허용함).
