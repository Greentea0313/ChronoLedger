# SRS 검토 재개 체크포인트

- 갱신일: 2026-10-02
- 목적: 현재 작업은 이 체크포인트 저장 후 멈춘다. 사용자가 나중에 재개를 요청하면 이 파일을 먼저 읽고, 남은 항목과 적절한 시작 지점을 확인한다.
- 현재 단계: 기획 결정 반영 및 SRS 초안 검토 중. SRS 기준선 승인 및 설계 단계 진입은 아직 하지 않았다.

## 사용자와 확정한 결정

1. **오프라인 만료 처리**: 오프라인은 인증 세션이 유효한 동안 캐시를 읽고 만료 항목 모달을 닫을 수 있다. 오프라인 쓰기는 비활성화한다. 온라인 복귀 시 과거 목표일의 미처리 `PLANNED` 항목을 다시 처리한다.
2. **과거 예정 취소 항목 복구**: 복구해도 원래 목표일을 유지한다. 목표일이 지난 상태라면 만료 처리 모달에 다시 표시한다.
3. **환불과 수동 포인트 보정**: 환불은 해당 결제 행의 포인트 사용 반환/예상 적립 회수만 처리한다. 별도의 `MANUAL_ADJUST`는 유지한다.
4. **총 자산 차감**: 기존 토글을 유지한다. `deduct_from_asset=true`면 실결제액을 차감하고 환불 시 복구한다. 오늘 결제는 기본 켬, 과거 내역은 기본 끔이며 사용자가 바꿀 수 있다.
5. **계정 삭제**: 본인 계정 삭제 시 개인 테이블 데이터와 비공개 아이콘도 삭제하고 공용 게임/일정은 보존한다. 계정 유지 중 개별 지출 삭제 금지와는 별도다.
6. **예산 0원**: 월별 예산 행이 없거나 월별 금액이 0원이면 기본 예산을 적용한다. 최종 적용 예산도 0원이면 비율 경고와 초과 확인을 생략한다.
7. **예산 초과 확인**: 예상 소비액을 증가시켜 100% 초과를 유발하는 등록·수정·복구·결제 변경은 저장/확정 전에 확인한다.
8. **포인트 적립 자격**: 실제 결제수단을 Google Play/Galaxy Store로 선택한 경우에만 해당 스토어 적립률로 `floor(final_amount * rate / 100)` 예상 적립을 한다. `WALLET` 결제는 스토어 포인트를 사용해도 적립하지 않는다. 실제 스토어 정산액 보장은 아니다.
9. **구독 템플릿 비활성화**: 연결된 기존 미결제 예정 회차를 `TEMPLATE_DEACTIVATION` 사유로 보존 취소한다. 재활성화는 미래 회차 생성을 재개할 뿐 기존 회차를 자동 복구하지 않는다.
10. **구독 취소 회차 복구**: 템플릿 비활성화 취소 회차는 템플릿을 먼저 재활성화한 후 명시적으로 복구한다. 사용자 직접 예정 취소는 템플릿 상태와 관계없이 복구할 수 있다.
11. **구독 템플릿 삭제**: 물리 삭제하지 않는다. 조회·추가·수정 및 비활성화만 허용한다.
12. **내 게임 제거와 아이콘**: `user_games`에서 게임을 제거할 때 그 게임의 사용자 커스텀 아이콘 Storage 객체도 삭제한다.
13. **날짜별 개인 메모 개수**: 같은 날짜에 여러 메모를 허용한다. 날짜 타일에는 도트 하나만 표시하고 상세 영역에서 해당 날짜의 메모를 모두 보여준다.

## 반영한 파일과 변경

- [SRS.md](../md/SRS.md): FR/NFR 식별자, 수용 기준, 권한·상태 전이·추적성을 작성하고 위 결정 및 SRS 대조에서 발견한 요구사항 누락을 보완했다.
- [SCHEMA.sql](../md/SCHEMA.sql): 신규 가입 기본 데이터 트리거, 취소 사유, 예정 취소/복구 RPC, 구독 비활성화 취소 트리거, 지출 참조 검증, 템플릿 DELETE 차단, 선택한 스토어 결제에 한정한 적립 산식을 반영했다.
- [SPEC.md](../md/SPEC.md), [resolved-blockers.md](../md/resolved-blockers.md), [revisions_and_decisions.md](../md/revisions_and_decisions.md): 최신 결정과 기준 우선순위를 반영했다. 통합 기획 파일의 복사된 예전 DDL은 참고용이며 SQL 초안은 `SCHEMA.sql`이 기준이다.
- `docs/architecture.md`, `docs/to-do.md`, `docs/progress.md`, `docs/handoff.md`, `docs/changelog.md`: 계정 삭제 Storage 정리, SQL 검증 게이트, 진행 상태와 다음 작업을 동기화했다.
- 기존 검토 기록 `md/srs-readiness-review.md`, `md/resolved-blockers-review.md`는 당시 검토를 보존하고 후속 SRS를 가리키도록 표시했다.

## 현재 검토 위치

- 사용자는 SRS 전체를 **항목별로 함께 검토**하는 방식을 선택했다.
- 검토 및 결정 보완은 캘린더/예산, 지출 취소·환불, 포인트 적립, 계정 삭제, 정기 구독 템플릿, SRS §4.8 아이콘 및 메모까지 진행했다.
- §4.8에서 내 게임 구독 제거 시 해당 게임의 커스텀 아이콘 Storage 객체도 삭제하고, 하루에 여러 개인 메모를 허용하되 타일에는 도트 하나만 표시하기로 결정했다.
- 다음 검토는 `md/SRS.md`의 **§5 외부 인터페이스 및 환경**부터 비기능 요구사항, 상태 전이, 오류 처리, 검증 게이트와 추적성을 기준 문서와 대조한다. 발견한 새 제품 결정을 한 번에 하나씩 사용자 입력창 선택지로 확인한다.
- 최종 승인 질문은 전체 대조가 끝난 뒤 한다. 지금은 사용자 승인 전인 초안이다.

## 검증 상태 및 남은 작업

- `git diff --check`로 패치 공백 검사를 수행했다. 최근 템플릿 변경 이후 재실행한다.
- PostgreSQL/Supabase 실행 검증 및 자동 테스트는 수행하지 않았다.
- 저장소에서 `supabase/**`, Docker Compose, 테스트 SQL 및 환경 예제 설정을 찾지 못했고 `README.md`만 확인됐다. SRS 승인 후 테스트 DB/검증 환경이 있는지 확인하고, 없으면 사용자에게 테스트용 환경 선택/제공을 물어본다. 운영 DB에 적용하지 않는다.
- SRS 전체 리뷰 및 사용자 승인 후 DB/RPC/RLS 실행 검증, 결과 반영, 설계 단계 진입 판정을 남겨둔다.
- 작업 중 생성된 사용자 변경은 보존한다. `git status`에서 `md/SKILL.md` 수정과 기존 문서 이동/삭제 및 미추적 문서를 확인했으며 이를 되돌리거나 정리하지 않는다.

## 재개 시 확인할 시작 지점

SRS §4.8(아이콘 및 메모) 검토는 2026-10-02 사용자 결정 반영으로 완료했다. 다음 시작 위치는 §5 외부 인터페이스 및 환경이다. 이어서 비기능 요구사항, 상태 전이, 오류 처리, 검증 게이트와 추적성을 검토한다. 질문은 한 번에 하나씩 UI 선택지 팝업으로 묻는다. SRS 전체 검토/사용자 승인과 안전한 테스트 DB에서의 SQL/RPC/RLS 실행 검증이 끝난 뒤 설계 단계 진입 여부를 판정한다.
