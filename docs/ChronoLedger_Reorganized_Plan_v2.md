# ChronoLedger 기획 재정리 및 구현 설계 가이드 (v2)

본 문서는 프로젝트의 승인된 기준 문서([SRS.md](../md/SRS.md), [SPEC.md](../md/SPEC.md), [detailed-design.md](detailed-design.md), [SCHEMA.sql](../md/SCHEMA.sql))와 사용자 피드백을 종합하여, **실제 라우트 구조, 화면별 UI 배치, 데이터 생성/수정 UI 진입점, 그리고 기능 간의 유기적 통제 규칙**을 명확히 정의한 최종 기획 가이드입니다.

---

## 1. 실제 라우팅 및 화면 계층 구조

ChronoLedger는 Next.js App Router 단일 코드베이스 기반으로, 상단바(`Topbar`)를 공유하는 대시보드 하위 라우트 구조를 중심으로 동작합니다.

```text
/ (루트: 로그인 여부에 따라 /auth 또는 /dashboard로 리다이렉트)
├── /auth (독립 레이아웃: 로그인 / 회원가입)
├── /dashboard (공통 Topbar 레이아웃: 홈, 소비, 게임, 설정)
│   ├── /dashboard (홈: 캘린더 메인 + 상세/예산 패널)
│   ├── /dashboard/expenses (소비: 가계부 목록 + 통계 분석 + 정기 구독 템플릿)
│   ├── /dashboard/games (게임: 내 게임 목록 및 구독 관리)
│   └── /dashboard/settings (설정: 프로필, 재무/지갑 관리, 내 요청 내역, 계정 삭제)
└── /admin (동일 Topbar 공유: 관리자 전용 일정/카탈로그 관리 - role=admin 전용)
    └── /admin/requests (사용자 요청 승인/반려 관리)
```

## 2. 화면별 UI 배치 및 데이터 진입점 (UI Interaction Points)

### 2.1 `/auth` (인증 화면)
* **역할**: 이메일/비밀번호 로그인, 회원가입, Google OAuth(PKCE) 인증.
* **UI 레이아웃**:
  * 공통 Topbar가 없는 독립 다크 테마 화면.
  * 입력 폼(이메일, 비밀번호)은 명시적 레이블과 탭 순서(이메일 → 비밀번호 → 로그인 → 가입 → Google)를 제공.
  * 모바일(320px~)에서도 가로 스크롤 없는 세로형 스택 레이아웃, 터치 영역 44px 이상 보장.

### 2.2 `/dashboard` (홈: 캘린더 메인)
* **역할**: 이번 달 일정, 개인 메모, 선택일 상세 내역 확인 및 당월 예산 소진 현황 요약.
* **UI 레이아웃 (Desktop)**:
  * 좌측 메인: 전체 월간 캘린더.
  * 우측 사이드바: 
    * 상단: **총 자산 및 스토어 포인트 요약 카드**, **당월 예산 소진율 게이지/배지 (80% 주의, 100% 위험)**.
    * 하단: **선택일 상세 패널** (해당 날짜의 공용 일정 배너, 지출 내역, 개인 메모 목록).
* **UI 레이아웃 (Mobile)**:
  * 상단: 월간 캘린더 및 상단 컴팩트 예산 게이지 바.
  * 하단: 달력 날짜 터치 시 올라오는 **바텀 시트(Bottom Sheet)**에 상세 내역 및 예산 요약 표시.
* **캘린더 타일 엄격 제한**:
  * **월간 캘린더 타일 안에는 금액, 지출 내역 텍스트, '결제 예정' 텍스트를 절대 표기하지 않습니다.**
  * 오직 **게임 아이콘**, **`VERSION`/`PICKUP` 기간 배너**, **단일 메모 도트(여러 개의 메모가 있어도 도트 하나)**만 렌더링합니다.
* **데이터 생성/편집 진입점**:
  * **메모 작성/수정/삭제**: 날짜 선택 시 나타나는 상세 사이드바/바텀 시트 내부에서 인라인으로 직접 작성 및 삭제 (`personal_memos`).
  * **지출 추가 진입**: 
    * 상세 패널의 `[+ 지출 추가]` 버튼 클릭 시 지출 등록 모달 오픈.
    * 지출 등록 시 **카테고리 선택이 기본**이며, 카테고리가 '게임'인 경우에만 [게임 선택] 드롭다운이 활성화됨.
    * 게임을 선택하면 해당 날짜가 포함된 그 게임의 **`VERSION` 일정에만 바인딩**됨 (`PICKUP`은 지출 바인딩 대상에서 제외하고 순수 캘린더 배너 일정용으로만 사용).

### 2.3 `/dashboard/expenses` (소비: 가계부 및 통계)
* **역할**: 지출 내역 조회/관리, 소비 분석 통계, 정기 구독 관리.
* **UI 레이아웃**:
  * **상단 헤더**: 페이지 제목, `[+ 지출 추가]` 버튼, 뷰 전환 탭(`[지출 내역 및 통계 | 정기 구독 탭]`).
  * **1) 지출 내역 및 통계 탭**:
    * **통계 영역**:
      * 카테고리별 비중: 한눈에 비율을 파악할 수 있는 **원그래프 (Pie Chart)**.
      * 월별 소비 추이: **세로 막대그래프 (Bar Chart)**.
      * **집계 기준**: 실제 발생한 순수 소비만을 분석하므로 **오직 `CONFIRMED` 지출만 집계** (`CANCELLED` 및 `PLANNED` 제외).
    * **목록 영역**:
      * Desktop: 정렬 가능한 **테이블(표)** (날짜, 게임 아이콘, 제목, 카테고리, 결제수단, 결제금액, 상태, 액션 버튼).
      * Mobile: 날짜별로 그룹화된 **카드 목록**.
      * 각 항목별 액션 버튼:
        * `PLANNED`: `[확정]`, `[취소]`.
        * `CONFIRMED`: `[환불]`.
  * **2) 정기 구독 탭**:
    * 등록된 활성/비활성 구독 카드 목록.
    * `[+ 구독 추가]` 버튼: 
      * 카테고리를 먼저 선택하며, **카테고리가 '게임'일 때에만 [게임 선택] 입력란이 표시**됨.
      * 제목, 결제 주기/유형, 기본 금액, 결제수단 입력.
    * 구독 활성화/비활성화 토글 스위치.

### 2.4 `/dashboard/games` (게임 관리)
* **역할**: 내가 구독 중인 게임 목록 확인, 커스텀 아이콘 등록/변경, 공용 게임 카탈로그 검색 및 구독 추가, 신규 게임/일정 요청.
* **UI 레이아웃**:
  * 내 구독 게임 그리드 카드: 기본 아이콘, 커스텀 아이콘 등록 버튼(256×256 WebP 자동 변환, 최대 100KiB), `[구독 해제]` 버튼.
  * 하단: 공용 게임 카탈로그 검색 및 `[구독 추가]` 버튼.
  * **`[+ 추가 요청]` 버튼**:
    * 클릭 시 모달에서 **[게임 추가 요청]** 또는 **[일정 추가 요청]** 중 하나를 선택.
    * **게임 추가 요청 선택 시**: '게임 제목'만 입력하는 간결한 템플릿 제공.
    * **일정 추가 요청 선택 시**: '게임 선택' → 해당 일정의 기간 설정(시작일~종료일), 일정 종류(`VERSION` 또는 `PICKUP`), 일정 제목/메모를 입력하는 템플릿 제공.

### 2.5 `/dashboard/settings` (설정 및 계정)
* **역할**: 개인 재무/예산 설정, 스토어 지갑 설정 및 잔액 보정, 내 건의/요청 내역 확인, 계정 삭제.
* **UI 레이아웃 (섹션별)**:
  * **재무 설정**: 총 자산(`total_asset`), 기본 월 예산(`default_budget`) 수정 폼 (`set_user_finance_settings` RPC 호출).
  * **스토어 지갑 관리**: 
    * **Google Play**: 5가지 공식 등급 중 선택 (`BRONZE` 0.1%, `SILVER` 0.11%, `GOLD` 0.13%, `PLATINUM` 0.16%, `DIAMOND` 0.2%).
    * **Galaxy Store**: 4가지 공식 등급 중 선택 (`일반` 0.1%, `스타` 0.1%, `프레스티지` 1.1%, `로열블루` 2.1%).
    * 지갑 잔액 수동 보정 폼: 목표 잔액과 사유 입력 (`adjust_wallet_balance` RPC 호출, 원장에 `MANUAL_ADJUST` 기록).
  * **내 요청 내역**: 본인이 제출한 게임/일정 요청 목록, 승인 상태(`PENDING`, `APPROVED`, `REJECTED`), 관리자 반려 사유(`admin_memo`) 조회.
  * **계정 삭제**: 영향도 안내 경고 문구 및 뚜렷한 확인 모달을 통한 계정 삭제 신청.

### 2.6 `/admin` 및 `/admin/requests` (관리자 전용)
* **역할**: 공용 게임 일정 직접 등록/수정, 사용자 게임/일정 추가 요청 승인 및 반려.
* **UI 레이아웃**: 동일한 Topbar를 공유하며, 상단에 `[공용 일정 관리 | 요청 관리]` 서브 탭 제공. 승인/반려 시 관리자 메모 입력 폼 제공.

## 3. 핵심 데이터 모델 및 생성/입력 명세 (Data & Form Specification)

### 3.1 지출(Expenses) 등록/수정 모달 명세
* **통화 단위**: 모든 금액은 **정수 KRW 단일 통화**로 관리합니다.
* **폼 입력 및 바인딩 흐름**:
  1. **제목 (`title`)**: 필수 (최대 150자).
  2. **카테고리 (`category`)**: 필수 ('게임', '정기 구독', '식비', '교통', '생활', '기타').
  3. **관련 게임 (`game_id`)**: 카테고리가 '게임'인 경우에만 노출.
  4. **버전 바인딩 (`schedule_id`)**: 게임 선택 시, 해당 결제일에 해당하는 **`VERSION` 일정**이 있으면 자동 추천/선택됨 (`PICKUP` 일정은 바인딩 제외).
  5. **목표 결제일 (`target_date`)**: 필수 (KST 기준 YYYY-MM-DD).
  6. **예상/정가 금액 (`original_price`)**: 필수 (0 이상).
  7. **결제수단 (`payment_method`)**: 필수 ('WALLET', 'GOOGLE_PLAY', 'GALAXY_STORE').
  8. **메모 (`memo`)**: 선택.
* **상태 결정 규칙**:
  * 입력한 결제일이 **KST 오늘 이전/당일**: `[확정으로 즉시 등록]` 또는 `[예정으로 등록]` 선택 가능.
  * 입력한 결제일이 **미래 날짜**: 무조건 `PLANNED`(예정 지출)로 강제 고정.

### 3.2 결제 확정 모달 (`process_expense_payment`) 명세
`PLANNED` 지출에서 `[확정]` 버튼 클릭 시 오픈되는 회계 확정 폼:
* **입력 필드**:
  * 정가(`p_original_price`), 일반 할인액(`p_discount_amount`).
  * 포인트 사용 여부 체크박스: 체크 시 사용 포인트(`p_used_points`) 및 포인트 할인액(`p_point_discount_amount`) 입력. 포인트 플랫폼(`p_point_platform`) 선택.
  * 최종 결제수단(`p_payment_method`): WALLET, GOOGLE_PLAY, GALAXY_STORE.
  * 자산 차감 토글(`p_deduct_asset`): 오늘 결제는 기본 켬(ON), 과거 날짜 입력은 기본 끔(OFF).
  * 실제 결제일(`p_payment_date`): KST 오늘을 초과하는 미래 날짜는 거부.
* **실시간 계산 표시**: 최종 결제액 = 정가 - 일반할인 - 포인트할인. 예상 포인트 적립량 = `floor(최종결제액 × 적립률 / 100)` (스토어 결제 시에만 적용).

## 4. 정기 구독 결제 주기/유형 확정 규격 (Confirmed Subscription Specification)

사용자 결정에 따라 **[A안: 주기 유형(cycle_type) 3종 분리 모델]**로 확정되었습니다.

### 4.1 구독의 3가지 주기 유형 (`cycle_type`) 명세
1. **매월 지정일형 (`MONTHLY_DAY`)**:
   * **대상**: OTT 서비스, 음악 스트리밍, 매월 고정 정기 결제.
   * **필드**: `billing_day` (1~31일).
   * **동작**: 매월 해당 일자에 당월 회차 예정 지출(`PLANNED`) 지연 생성 (말일 자동 보정).
2. **30일 누적 충전형 (`INTERVAL_30`)**:
   * **대상**: 원신 '공월 축복', 붕괴 스타레일 '열차보급허가증', 명일방주 '월정액' 등.
   * **동작**: 고정 일자가 아닌 **이전 결제 확정일 기준 +30일 뒤**를 목표일(`target_date`)로 하여 다음 회차 생성.
   * **누적 갱신**: 사용자가 만료일 이전에 추가로 결제 확정 시, 기존 만료 예정일로부터 +30일이 연장되어 누적 스택 갱신.
3. **게임 버전 패스형 (`VERSION_PASS`)**:
   * **대상**: 배틀패스, 진주 기행, 무명객의 영광 등.
   * **활성화 조건**: 카테고리가 '게임'이고 특정 게임이 선택된 경우에만 활성화.
   * **동작**: 날짜가 아니라 **관리자가 등록한 해당 게임의 새로운 `VERSION` 시작일**에 맞춰 자동으로 해당 버전 회차 예정 지출 생성 및 버전 바인딩(`schedule_id`).

### 4.2 데이터 스키마 및 회차 생성 규칙
* `subscription_templates`에 `cycle_type VARCHAR(20) NOT NULL DEFAULT 'MONTHLY_DAY' CHECK (cycle_type IN ('MONTHLY_DAY', 'INTERVAL_30', 'VERSION_PASS'))` 적용.
* 회차 중복 생성 방지:
  * `MONTHLY_DAY`: `(template_id, billing_cycle)` 부분 유니크 인덱스로 당월 1회 생성 보장.
  * `INTERVAL_30`: 이전 활성 회차의 결제 완료 전까지는 다음 회차를 중복 생성하지 않음.
  * `VERSION_PASS`: `(template_id, schedule_id)` 유니크 조건으로 버전당 1회 생성 보장.

## 5. 기능 간 유기적 연결 및 엄격한 통제 규칙 (Domain Connection Constraints)

1. **회계 원자성 보장**:
   * 결제 확정은 반드시 `process_expense_payment` 단일 RPC 트랜잭션으로 처리 (지출 확정 + 포인트 차감/적립 + 자산 차감).
   * 환불은 반드시 `refund_expense_payment` RPC로 처리. 상태는 `status: CANCELLED`, `cancellation_kind: PAYMENT_REFUND`로 전이되며 당월 예산 집계에서 즉시 제외.
2. **공용 일정 변경 시 동기화 및 확정 지출 불변성**:
   * 관리자가 `VERSION` 일정을 변경하면 DB 트리거에 의해 바인딩된 `PLANNED` 지출의 날짜(`start_date`, `end_date`, `target_date`)만 동기화됨.
   * 이미 결제 완료된 **`CONFIRMED` 지출은 일정이 바뀌어도 결제일이 절대 변하지 않음**.
3. **예산 계산 일원화 및 100% 초과 확인 모달**:
   * 월 예상 소비액 = `CONFIRMED(결제일 기준) + PLANNED(종료일 또는 목표일 기준) 합산`.
   * 사이드바/상단 예산 바에서 80% 주의, 100% 위험 배지 표시. 100% 초과 지출 발생 시 저장 전 필수 컨펌 다이얼로그 강제.
4. **만료된 지출(Expired Planned) 필수 해결 모달**:
   * KST 오늘 기준 목표일이 과거인 미결제 지출이 있을 경우, 온라인 진입 시 전체 화면 모달로 강제 해결 요구 (1. 결제 확정, 2. 예정 취소, 3. 다음 가능한 버전 일정으로 이동). 처리 전까지 캘린더 상호작용 차단.
5. **게임 구독 해제 시 데이터 보존**:
   * 게임 구독을 해제해도 기존 지출(`expenses`) 데이터는 절대 삭제/취소되지 않고 온전히 유지됨 (캘린더 공용 배너만 필터링).
6. **오프라인 제약**:
   * 유효 세션에 한해 IndexedDB 읽기만 허용, 쓰기 버튼 전체 비활성화, 쓰기 큐 배제, 세션 만료 시 개인정보 즉시 숨김.
